# DESIGN

## Visual Thesis
云端回信的视觉不是“温柔卡片堆叠”，而是一座带纸张质感的安静邮局。
核心感受是克制、留白、时间差和仪式感，不是高频互动或即时反馈。

## Principles
1. 每个页面只有一个主视觉重点。
2. 首页负责定调，主流程负责仪式感，管理页负责信息组织。
3. 纸张、邮戳和暖石色是母题，不允许到处复制成装饰噪音。
4. 默认不用卡片堆叠制造层级；能用排版、留白、分割和单一重点解决，就不要加新容器。
5. 回响相关页面优先营造“打开一封信”的感觉，管理相关页面优先保证扫描效率。

## Tokens
- Background
  - `linen`: 页面底色，承接全局背景纹理。
  - `parchment` / `parchment-strong`: 信纸和浮层主色。
- Text
  - `ink`: 最强标题色。
  - `charcoal`: 正文主文字色。
  - `driftwood`: 说明文字色。
  - `fog`: 次级标签与占位色。
- Accent
  - `stone`: 主行动色与主要强调色。
  - `amber`: 等待状态。
  - `sage`: 已送达状态。
  - `terracotta`: 危险和边界警示。
- Shape
  - 大面板圆角统一使用 `24px` 到 `32rpx` 的软圆角，不使用硬边小圆角。
- Shadow
  - `card`: 常规信息面板。
  - `panel`: 首页主面板、重点信息。
  - `lifted`: 仅用于首屏主视觉或信纸英雄态。

## Typography
- 显示标题使用 `var(--font-display)`，正文与辅助信息使用 `var(--font-sans)`。
- 页面标题、主视觉标题、信纸中的重要标题允许使用衬线气质；数据和管理页正文不使用花哨排版。
- 不允许用过多字号制造层级。常用只保留 `display / heading / body / caption / overline` 五档。

## Components
- `PageShell`
  - 统一页面外壳，负责 eyebrow、标题、副标题、hero、footer 结构。
  - 有固定底部 CTA 时必须自动补足安全区和底部留白。
- `ArcoButton`
  - `primary`: 主任务提交。
  - `outline`: 次级动作或状态切换。
  - `text`: 轻量操作、返回、危险操作。
- `ArcoCard`
  - `emphasis`: 页面唯一重点信息。
  - `default`: 普通内容。
  - `muted`: 次级信息或过渡区域。
  - `danger`: 破坏性操作容器。
- `LetterPaper`
  - 只用于写信正文和回响正文等真正需要“纸张感”的内容，不把所有信息都放进信纸里。
- `FormField`
  - 任何可编辑字段都必须有显式标签和说明，不能只依赖 placeholder。

## Motion
- 默认保留轻微入场、浮动和展开动效，但节奏必须克制。
- 动效只服务于“投递”“打开”“等待”三类叙事，不做无意义悬浮效果。
- 必须提供 `prefers-reduced-motion` 退化路径。

## Accessibility And Web Rules
- H5 端优先给真正的操作元素按钮语义；复杂卡片交互保持小程序兼容时，至少保留清晰的点击热区和焦点样式。
- 表单必须有显式标签、说明、禁用态和错误提示。
- 固定底部 CTA 不能遮挡正文或最后一个操作区域。
- 小屏宽度 `<= 360px` 时不允许标题溢出、不允许三列输入硬挤同一行。

## Page Intent
- 首页：像一张海报，负责让用户理解“这是一座安静的邮局”。
- 写信：像在真正落笔，字段有清晰标签，但不打断情绪。
- 已投递 / 回响详情：把等待与打开做成仪式性的体验。
- 收件箱 / 纪念档案 / 我的：减少情绪化装饰，提升扫描和管理效率。
